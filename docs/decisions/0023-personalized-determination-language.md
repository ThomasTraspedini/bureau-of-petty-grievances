# 0023 — Personalized determination language

## Status

Accepted.

## Context

The deterministic determination is complete, safe, and useful, but a single evaluator journey can make provider-backed linguistic realization difficult to perceive. The earlier pipeline also asked the provider to reproduce deterministic metadata and grounding arrays. That enlarged the failure surface without adding expressive value, especially across six localized editorial contracts.

The filed witness statement should not appear as an unexplained copy-and-paste quotation. The Bureau’s product voice is better served by an official transcription: a formal paraphrase whose involuntary humor comes from disproportionate administrative care, adapted to the conventions of each language.

## Decision

Use `gpt-5.6-terra` as the configurable default provider model with low reasoning effort and an 18-second owned request timeout. The provider produces prose only. The owned adapter attaches schema version, locale, disposition, and section grounding deterministically before the existing locale-specific safety and editorial validators run.

Each locale prompt includes its deterministic language as a semantic reference. This exposes the exact localized factual and remedy vocabulary required by validation while explicitly requiring original prose. The allegation is written as an official transcription of the filed account rather than a quotation. The finding should include one precise, unexpectedly attentive administrative observation grounded only in submitted facts. The deterministic version remains the complete fallback.

During evaluation access only, the transient browser session records whether personalized language was accepted or the standard formula was used. When personalized language succeeds, the evaluator may compare its official transcription, finding, and remedy with the deterministic standard. This diagnostic:

- is absent from standard and anonymous sessions;
- names neither the provider nor model, cost, quota, request identifier, or raw failure reason;
- is not part of the issued determination snapshot;
- is not persisted or published with a public record.

This is a narrow evaluation exception to the source-opacity rule in decision 0010. Public and standard product surfaces continue to present provider and fallback language with the same hierarchy and authority.

## Consequences

- Provider reliability no longer depends on generated metadata or grounding arrays.
- Locale validation remains authoritative and deterministic rather than being weakened to accept plausible-looking prose.
- The value of personalized realization is inspectable in one evaluator journey without creating a public product tier.
- A provider failure still completes the filing with localized deterministic language and consumes no successful-generation credit.
- Existing public-record and determination snapshot schemas remain unchanged.

## Open considerations

Model promotion beyond `gpt-5.6-terra` still requires the same schema, locale, safety, and editorial evaluation. Public provenance, selectable writing styles, and alternative public versions remain outside the product contract.
